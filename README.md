# Супервизия 2.0 — таск-менеджер с отчётностью по периодам

Приложение больше не привязывает жизненный цикл задачи к календарному месяцу.

## Основная логика

- **Задача создаётся один раз** и живёт до фактического завершения или отмены/провала.
- У задачи есть постоянные поля: статус, приоритет, дата начала, дедлайн, дата завершения, результат, следующий шаг и блокер.
- **Родительские и дочерние задачи** видны в карточке и открываются по клику.
- ID задачи копируется одной кнопкой.
- Для сквозных задач есть блок **«Ход работы / обновления»**: короткая запись + фактическая дата. Эти записи позволяют корректно собирать отчёт за любой период.
- **Планирование** ведётся между двумя произвольными датами, например между супервизиями. Включение задачи в период не создаёт её копию.
- **Отчёт и аналитика** строятся по произвольному диапазону дат.
- Проекты могут быть **без направления**. На обзоре они относятся к разделу **«Прочее»**.

## Фильтры задач

На странице «Задачи» доступны:

- все задачи;
- все активные;
- все завершённые;
- все проваленные;
- сроки: все, ближайшая неделя, текущий месяц;
- направление, проект и текстовый поиск.

## Супервизии

Для каждой супервизии можно указать:

- дату встречи;
- начало отчётного периода;
- главные результаты;
- трудности / вопросы;
- решения;
- фокус следующего периода;
- дату следующей супервизии.

Если следующая дата указана, приложение может сразу открыть планирование нового периода.

## Совместимость с версией 1.0

Используется прежний ключ LocalStorage (`work-supervision-v1`), поэтому существующие данные не создаются заново. При первом запуске версия 2.0 автоматически переносит последние месячные статусы/сроки/результаты в постоянные поля задач и сохраняет старую месячную историю в JSON.

## Запуск

Приложение статическое. Для GitHub Pages достаточно разместить в корне репозитория:

- `index.html`
- `styles.css`
- `app.js`
- `.nojekyll`
