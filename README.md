# Задачник 3.0

Задачи, проекты и отчётность между супервизиями. Готовое статическое приложение: сборка, серверная база и установка библиотек для работы не нужны.

## Обновление с версии 2.2

1. В прежнем приложении скачайте резервную копию JSON из «Настроек» или «Отчёта».
2. Закройте вкладки прежней версии.
3. Распакуйте архив. Замените файлы приложения содержимым папки `zadachnik-v3.0`. Файл `index.html` должен находиться в той же папке публикации, что и раньше.
4. Откройте приложение по прежнему адресу в том же браузере. При необходимости выполните полное обновление страницы: Ctrl+F5.
5. Данные перенесутся автоматически. В «Настройках» появится исходная резервная копия и замечания к старым данным, если они нужны.

Если приложение размещено в существующем репозитории GitHub Pages, загрузите содержимое папки в прежнее место публикации. Адрес сайта и настройки публикации менять не требуется. Не удаляйте собственный файл `CNAME`, если он используется. В архиве есть `.nojekyll`.

Если вы открыли приложение с другого адреса, на другом устройстве или из другой папки и увидели начальные данные: откройте «Настройки → Импорт JSON» и загрузите свою копию. Перед заменой приложение покажет количество записей и сделает резервную копию текущей базы.

Не открывайте старую и новую версии одновременно на одном адресе. Для возврата к старой версии используйте исходную копию старого формата, а не экспорт версии 3.0.

## Первый запуск

Для локального просмотра откройте `index.html`. Для постоянной работы можно использовать прежний статический хостинг. Все файлы приложения должны оставаться рядом.

На чистом запуске сохранён исходный набор проектов и задач из версии 2.2. Это начальные данные, а не сведения из вашей рабочей базы: её приложение читает из браузера либо из импортированного JSON.

## Что исправлено и добавлено

- Данные и зависимые показатели обновляются после изменения без перезагрузки страницы. Другие вкладки этого браузера также получают изменения.
- История статусов и полей задачи позволяет рассчитывать состояние на конец периода. Завершение после конца периода больше не удаляет задачу из прошлой отчётности.
- Повторное открытие задачи очищает текущую дату завершения, сохраняя прежнее событие в истории.
- Отчёт и аналитика используют общие расчёты. Группы задач и предложения исключены из показателей выполнения обычных задач.
- Сохранённые версии отчётов не меняются при последующем редактировании задач. Можно создать новую версию.
- В отчёт включены проваленные и отменённые задачи, причины и следующие действия.
- CRM сравнивает последние известные состояния на начало и конец периода. В отчёте отображаются все 11 стадий.
- Количества CRM — целые неотрицательные числа; пустое поле означает отсутствие данных. Создание второго среза на ту же дату запрещено. Старые дубликаты остаются доступными для проверки.
- Копирование CRM использует последний срез не позже выбранной даты, в том числе из другого месяца.
- Карточка показывает родителя и дочерние задачи, содержит переходы по клику и кнопку копирования ID. Циклические связи запрещены.
- Группы показывают прогресс своих дочерних задач. У задачи есть архивирование; история и отчёты сохраняются.
- Проекты без направления отображаются в «Прочем».
- Список планирования больше не обрезается до 30 задач; доступен поиск.
- Фильтры на «Обзоре» и в «Задачах» независимы. По умолчанию видны активные задачи любых периодов. Есть все / завершённые / проваленные / отменённые / архив, неделя, месяц и просрочки. Можно фильтровать по дедлайну или дате завершения.
- Проверяются периоды, даты, связи, ID и структура импорта. Повреждённая база не заменяется начальными данными.
- Автоматические резервные копии создаются перед переносом, импортом и восстановлением. Хранятся последние пять.
- Светлое оформление на основе второго референса, сворачиваемое меню, мобильная навигация и минималистичная иконка «Порядок».

## Ежедневная работа

1. Создайте задачу один раз и выберите проект. Дедлайн может быть любым или отсутствовать.
2. При необходимости назначьте родителя. Дочерняя задача может иметь собственные сроки.
3. Вносите короткие датированные записи в «Ход работы».
4. После завершения заполните «Результат». Для отказа от работы используйте «Отменено», для невыполненного обязательства — «Провалено» и причину в поле «Что мешает».
5. Убирайте неактуальные записи в архив: они не мешают текущему списку, но сохраняются в истории.

Изменения существующей задачи сохраняются автоматически. Для создания новой задачи нажмите «Создать задачу». Поле «Дата изменения» позволяет указать фактический день изменения задним числом. Будущая дата допустима для дедлайна и планирования, а фактическое завершение и запись о работе не могут быть в будущем.

## Супервизии и отчёты

1. В «Супервизиях» укажите дату встречи и начало отчётного периода.
2. Нажмите «Отчёт этой супервизии»: точные даты и решения встречи перейдут в отчёт.
3. Проверьте результаты, продолжающуюся работу и CRM, затем нажмите «Зафиксировать отчёт».
4. Сохранённую версию можно открыть из списка, скачать в HTML, распечатать / сохранить в PDF либо выгрузить данные в CSV.
5. Укажите дату следующей супервизии и нажмите «Планировать следующий период». Добавляйте существующие задачи в план без создания копий.

Обе даты диапазона включаются. Например, первый отчёт: **28.09.2026–02.11.2026**, следующий: **03.11.2026–дата следующей встречи**. Так события дня супервизии не дублируются. Месяц и неделя — быстрые фильтры; задачи к ним не привязаны.

«Завершено» означает событие завершения в периоде; «Активно на конец» — состояние на последнюю дату. Поэтому завершённая, а затем повторно открытая задача может присутствовать в обоих показателях. Одна задача учитывается не более одного раза в каждом исходе за выбранный период. Изменения одного дня упорядочены по времени внесения.

Печать доступна на странице «Отчёт». В окне печати браузера выберите «Сохранить как PDF». Скачиваемый HTML содержит собственное оформление и может быть открыт отдельно от приложения.

## Старые данные и точность истории

Версии 1.x–2.2 не сохраняли полную историю всех изменений. Восстановить отсутствующие сведения автоматически невозможно. Отчёты, затрагивающие такие данные, содержат соответствующую пометку.

Месячные итоги без точного дня, а также обнаруженные даты, которые прежняя миграция подставляла как 28-е число или дедлайн, помечаются для уточнения. Они не подменяются выдуманной точной датой. Уточнить завершение можно в карточке задачи; день старой заметки — в «Ходе работы»; день супервизии — в её карточке.

В исходной резервной копии сохранены прежние данные без изменений. Старые месячные записи также остаются внутри JSON; месячные планы доступны как периоды планирования. Завершённые задачи без точной даты не включаются в дневные показатели завершения до уточнения даты.

Сохранённый отчёт фиксирует также названия проектов, направления, CRM и решения встречи. У последующего текущего расчёта группировка проектов может отражать новые названия и направления; ранее зафиксированная версия остаётся неизменной.

## Хранение данных

База хранится локально в браузере. Автоматическая синхронизация между устройствами не подключена. Очистка данных сайта или удаление профиля браузера удаляет и базу, и локальные резервные копии, поэтому периодически скачивайте JSON.

При ошибке сохранения интерфейс показывает «Не сохранено». При повреждении базы открывается экран восстановления с возможностью скачать исходные данные или импортировать копию. Смена адреса сайта создаёт отдельное хранилище браузера.

## Файлы для разработки

- `model.js` — модель, история, миграция, валидация и единые расчёты.
- `storage.js` — сохранение, резервные копии и обмен между вкладками.
- `app.js` — экраны и обработчики действий.
- `styles.css` — общая система компонентов, адаптивная и печатная вёрстка.
- `seed.js` — исходные проекты и задачи.
- `icon.svg` и PNG/ICO — знак приложения, favicon и иконки установки.
- `tests/model.test.cjs` — автоматические проверки модели.
- `CHECKS.md` — выполненные проверки сборки.

Для запуска проверок модели нужен Node.js; само приложение в Node.js не нуждается:

```bash
node --test tests/model.test.cjs
```

Схема данных: 3. Ключ браузерного хранилища сохранён: `work-supervision-v1`.
